# テスト方針

## 1. 基本方針

本プロジェクトは、個人利用・ローカル利用を前提とした小規模アプリケーションである。  
そのため、過剰なテスト体制を持ち込まず、手元で簡単に確認できる範囲で軽くテストを行う。

テストの目的は、次の 2 点に絞る。

* 重要な不具合を早く見つける
* 変更時に壊れた動作を防ぐ

---

## 2. 対象とするテスト

### 2.1 API テスト

API の主要な正常系と異常系を軽く確認する。

対象例:
* 一覧取得
* 登録処理
* 更新処理
* 削除処理
* バリデーションエラー

確認ポイント:
* HTTP ステータスコード
* 共通レスポンス形式
* エラーメッセージの妥当性

### 2.2 重要ロジックの確認

複雑になる処理だけ、必要最低限で確認する。

対象例:
* 条件分岐
* 変換ロジック
* 論理削除の判定
* 重要な計算や整理処理

特別に難しいロジックがない場合は、手動確認で十分とする。

---

## 3. テストしないもの

次は現時点では対象外とする。

* 画面の UI テスト
* 見た目の細部確認
* ブラウザ操作の自動テスト
* 過剰な E2E テスト

画面の見た目や操作感は手動確認で十分とする。

---

## 4. 実施方針

初期段階では、以下を優先する。

1. API の正常系 / 異常系
2. 重要なビジネスロジック
3. 例外時のエラーハンドリング

過剰な網羅は避け、壊れやすい箇所だけを確認する。  
自分が使う前提のため、テストは軽く、簡潔に、実用的に行う。

---

## 5. CI での確認

GitHub Actions では、最低限の静的確認を行う。

* `pnpm install`
* Prisma Client generate
* `pnpm exec tsc --noEmit`
* `pnpm lint`
* `pnpm build`

本プロジェクトでは、重いテスト自動化は行わず、必要に応じて API の軽い確認だけを追加する。
